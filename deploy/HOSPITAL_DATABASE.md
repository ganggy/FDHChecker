# ฐานข้อมูล HOSxP ของแต่ละโรงพยาบาล

เลือก **MySQL/MariaDB** หรือ **PostgreSQL** ที่ **ตั้งค่าระบบ → ฐานข้อมูล HOSxP** ได้โดยผู้ดูแลระบบ ระบุชื่อฐานข้อมูลตามโรงพยาบาลได้ ไม่จำเป็นต้องชื่อ `hos`

## ขอบเขตการรองรับ

| ส่วน | MySQL/MariaDB | PostgreSQL |
| --- | --- | --- |
| การเชื่อมต่อ HIS | รองรับ | รองรับ ผ่าน `pg` |
| ชื่อฐานข้อมูลและพอร์ต | กำหนดได้ | กำหนดได้ พร้อม schema |
| การอ่าน HIS | SQL เดิม | แปลง SQL ที่รองรับด้วย syntax tree และส่งค่าแบบ parameterized |
| การเขียน/สร้างตารางใน HIS | ตามสิทธิ์บัญชีเดิม | ปิด: connection ใช้ read-only และปฏิเสธคำสั่งเขียน |
| ฐานผู้ใช้และ REP/STM | MySQL/MariaDB | ต้องมี MySQL/MariaDB แยกต่างหาก |

**PostgreSQL ยังไม่เทียบเท่าการรองรับ MySQL ทุกเมนู**: เป็นการรองรับการเชื่อมต่อและการอ่าน SQL ที่ผ่านตัวแปลง ยังต้องทดสอบรายงานกับ HOSxP PostgreSQL ของโรงพยาบาลปลายทาง ฟังก์ชันแก้ไขข้อมูล การสร้างตารางประกอบใน HIS, JOIN ข้ามฐานข้อมูล และ SQL ที่ยังไม่รองรับจะถูกปฏิเสธ ไม่แปลงคำสั่งเขียนโดยคาดเดา

PostgreSQL บังคับ `GROUP BY` และชนิดข้อมูลเข้มงวดกว่า MySQL บาง query เดิมอาจต้องปรับรายงานโดยเฉพาะ การผ่านการทดสอบเชื่อมต่อไม่ได้รับรองว่าทุกกองทุนและการส่งออกทำงานครบ

ตัวแปลงเพิ่ม primary key ของตารางมิติที่ JOIN แบบหนึ่งต่อหนึ่ง เช่น `patient.hn` และ `pttype.pttype` ลงใน `GROUP BY` โดย PostgreSQL ต้องพบ primary key จริงใน schema จึงจะยอมรับคอลัมน์ประกอบ ระบบไม่เลือกค่าผู้ป่วยแบบสุ่มเพื่อหลบข้อผิดพลาดการจัดกลุ่ม

การอ่านสถานะ FDH สำหรับรายการ OPD/IPD อ่านฐาน REP/STM ผ่าน connection ของฐานนั้นแล้วจับคู่ VN/AN ในแอป จึงไม่ผูกกับชื่อ `repstminv` หรือบังคับให้ฐานทั้งสองอยู่บนเซิร์ฟเวอร์เดียวกัน

## ตั้งค่าผ่านหน้าเว็บ

1. เข้าระบบด้วยผู้ดูแล แล้วเปิดแท็บฐานข้อมูล HOSxP
2. เลือกชนิดฐานข้อมูล ระบุ Host, Port, ชื่อฐานข้อมูล และบัญชี สำหรับ PostgreSQL ระบุ schema เช่น `public`
3. เมื่อเปลี่ยนเซิร์ฟเวอร์ ชนิดฐานข้อมูล หรือบัญชี ต้องกรอกรหัสผ่านอีกครั้ง ปุ่มล้างรหัสผ่านใช้เฉพาะบัญชีที่ตั้งใจไม่มีรหัสผ่าน
4. กด **ทดสอบการเชื่อมต่อ** ระบบอ่าน metadata เพื่อตรวจตารางหลักและคอลัมน์โดยไม่อ่านชื่อผู้ป่วย
5. กด **ตรวจสอบและบันทึกการเชื่อมต่อ** ระบบทดสอบซ้ำและจะไม่บันทึกหากตารางหลักไม่ครบ
6. รีสตาร์ต backend ด้วยตัวจัดการ process ที่ใช้ติดตั้ง แล้วตรวจสถานะและรายงานของโรงพยาบาล

การบันทึกไม่สลับ connection ที่กำลังทำงาน ไฟล์ค่าที่บันทึกมีผลหลังรีสตาร์ต จึงต้องรีสตาร์ตทุก backend instance หากมีหลาย process

ค่าที่บันทึกอยู่ใน `.secrets/hospital-database.json` ของ working directory หรือเส้นทาง `HOSXP_CONFIG_FILE` ซึ่งมีความสำคัญเหนือ `HOSXP_*` ใน `.env` ต้องใช้ working directory และบัญชี service เดียวกันสำหรับ server และ CLI รายงาน หากใช้ container ให้ mount ไฟล์นี้ใน persistent volume และจำกัดสิทธิ์อ่านให้บัญชี service เท่านั้น ห้ามนำไฟล์นี้เข้า Git หรือส่งออกกับ template โรงพยาบาล

## ตั้งค่าผ่าน environment สำหรับการติดตั้งครั้งแรก

```dotenv
HOSXP_DB_TYPE=postgresql
HOSXP_HOST=YOUR_HIS_HOST
HOSXP_PORT=5432
HOSXP_DB=YOUR_HOSPITAL_DATABASE
HOSXP_SCHEMA=public
HOSXP_USER=YOUR_READONLY_USER
HOSXP_PASSWORD=YOUR_PASSWORD
HOSXP_SSL=true

# ฐานภายใน FDH Checker ยังคงเป็น MySQL/MariaDB
REPSTM_HOST=YOUR_APP_DATABASE_HOST
REPSTM_PORT=3306
REPSTM_DB=repstminv
REPSTM_USER=YOUR_APP_USER
REPSTM_PASSWORD=YOUR_APP_PASSWORD
```

SSL เปิดการตรวจใบรับรองด้วย ต้องติดตั้ง CA ที่เชื่อถือได้บนเครื่อง backend สำหรับระบบที่ใช้ CA ภายใน ไม่ปิดการตรวจใบรับรองเพื่อแก้ข้อผิดพลาด

ฐาน app settings เดิมเก็บใน HIS MySQL; เมื่อใช้ HIS PostgreSQL จะเก็บ app settings ในฐาน REP/STM แทน ระบบไม่คัดลอกค่าหน่วยบริการของโรงพยาบาลเก่าให้อัตโนมัติ ตั้งค่าหน่วยบริการและ mapping ให้ตรงกับโรงพยาบาลใหม่

หากเลือก PostgreSQL ผ่านหน้าเว็บ ไฟล์ override จะเปลี่ยนเฉพาะฐาน HIS ส่วน login และ REP/STM ยังคงใช้ `REPSTM_*` หรือ fallback ไปยังค่า `HOSXP_*` เดิมเพื่อรักษาการเข้าสู่ระบบของ installation เดิม หากตั้ง PostgreSQLผ่าน `HOSXP_*` ตั้งแต่เริ่มติดตั้ง ต้องกำหนด `REPSTM_HOST`, `REPSTM_PORT`, `REPSTM_DB`, `REPSTM_USER` และ `REPSTM_PASSWORD` ให้ครบ

## ก่อนเปิดรายงานจริง

- ตรวจสิทธิ, Lab, ยา, ADP และหัตถการของโรงพยาบาลปลายทาง
- เทียบจำนวน Visit และยอดเงินจากช่วงข้อมูลตัวอย่างกับรายงาน HOSxP
- ตรวจว่าเมนูที่ต้องใช้ผ่านทั้งกรณีมีข้อมูล ไม่มีข้อมูล และข้อมูลไม่ครบ
- งานที่ต้องเขียนกลับ HIS PostgreSQL ยังไม่เปิดใช้งานในรุ่นนี้
- สคริปต์ `backup-databases.sh` สำรอง MySQL/MariaDB หาก HIS เป็น PostgreSQL ให้ใช้กระบวนการสำรอง PostgreSQL ของโรงพยาบาลแยกต่างหาก ห้ามตั้ง `FDH_BACKUP_HOSXP=1` กับ PostgreSQL

## การทดสอบในโค้ด

`npm run test:hospital-db` ทดสอบค่าตั้ง การปิดบัง secret และประมวลผล SQL ที่แปลงบน PostgreSQL ผ่าน PGlite ในหน่วยความจำ ใช้ข้อมูลสมมติ ไม่เชื่อมต่อฐานโรงพยาบาลจริง

การทดสอบครอบคลุมการแปลง query รายการ Visit และกองทุนที่เปิดใช้ การรันรายงาน DRUGP บน schema HOSxP จำลอง การรวมสถานะ FDH ข้ามฐาน และการปฏิเสธผลรายงาน/ไฟล์ส่งออกเมื่อ query ล้มเหลว แม้โค้ดรายงานเดิมจะจับ error แล้วคืนรายการว่างก็ตาม ยังไม่ใช่การรับรองผลทุกกองทุนบนฐานโรงพยาบาลปลายทาง
