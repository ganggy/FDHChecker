# Audit และตรวจ STM 0 / Sheet 0

## วิธีใช้งาน

เปิดเมนู **การเงิน/ลูกหนี้ → ตรวจ STM 0 / Sheet 0** ได้โดยตรง
หรือใช้ปุ่มทางลัดจากหน้ากระทบยอดและหน้ารับ REP/STM

1. หน้า **กระทบยอด REP / STM / INV Visit** เลือกช่วงวันที่บริการและสิทธิ โหลดข้อมูล
   ดูรายการยอดต่าง รอ REP หรือรอ STM/INV ดาวน์โหลด **สรุป Audit ผู้บริหาร**
   ซึ่งรวมทุก Visit ตามตัวกรอง ส่วน Excel รายละเอียดเดิมส่งออกเฉพาะหน้าปัจจุบัน
2. หน้า **ตรวจ STM 0 / Sheet 0** เลือกช่วง **วันที่นำเข้าไฟล์**
   ไม่ใช่วันที่บริการ เพื่อรวมแถวที่ไม่มีวันที่บริการหรือจับคู่กับ HIS ไม่ได้ด้วย
3. กรองขั้นตอนติดตาม รหัสเหตุผล HN/VN/AN/TRAN_ID หรือไฟล์
   เปิด **ดูต้นทาง / HIS** เพื่อเทียบแถวต้นฉบับกับวินิจฉัย หัตถการและรายการค่าใช้จ่ายปัจจุบัน
   หน้านี้อ่านข้อมูล ไม่แก้ไข HIS และไม่ส่งเคลม
4. รายการที่มีการยืนยัน VN/AN และ HN กับ HIS, ยอดจ่ายระบุชัดเป็น 0,
   ไม่พบเงิน STM/INV ใน Visit หรือ TRAN_ID เดียวกัน และไม่อยู่กลุ่มรออนุมัติ/
   ทักท้วง/รอจ่าย จึงเลือกเข้า **เตรียมรายการแก้ไข / ส่งใหม่** ได้
   การเลือกได้เป็นเพียงเงื่อนไขทางข้อมูล ไม่รับรองสิทธิเบิกหรือสิทธิส่งใหม่
5. แก้ไขข้อมูลผ่านระบบงานที่รับผิดชอบ ตรวจสิทธิแก้ไขในระบบปลายทาง
   บันทึกสิ่งที่ตรวจและยืนยัน แล้วดาวน์โหลดรายการดำเนินงาน
   หากช่องทางเดิมคือ FDH เลือกเปิดส่งออก OPD/IPD เฉพาะรายการที่เลือก
   ระบบอ่านสถานะจับคู่และยอดจ่ายล่าสุดอีกครั้งก่อนส่งต่อ
   หน้าส่งออกยังตรวจ Preflight, Approve Code และการยืนยันส่งซ้ำตามเดิม
   หากเป็น eClaim/OSR ดาวน์โหลดรายการไปดำเนินการตามช่องทางนั้น
6. ดาวน์โหลด **สรุปผู้บริหาร** ในหน้า STM0 เพื่อเสนอจำนวนประเด็นตามขั้นตอน
   รายงานไม่มีชื่อ/HN/CID เป็นจำนวนแถวทั้งหมดตามตัวกรองพร้อมเวลาประมวลผล

## ความหมายและข้อควรตรวจจากเอกสาร

เอกสารชี้แจง eClaim ของ สปสช. ระบุ Data sheet 0 เป็นรายการจ่ายชดเชย
0 บาทพร้อมเหตุผล และยกตัวอย่าง HERB_GB ที่รอประมวลผลจ่ายสิ้นปีงบประมาณ
ดังนั้นยอด 0 เพียงอย่างเดียวไม่ยืนยันว่าต้องแก้ไขส่งใหม่
[เอกสารชี้แจง eClaim ยาสมุนไพร 23 พ.ค. 2568 (สำเนาที่โรงพยาบาลเผยแพร่)](https://www.kpnhospital.com/wp-content/uploads/2025/09/ระบบโปรแกรม_e-Claim_ยาสมุนไพร_HERBFS_25680523.pdf)

เอกสาร Provider Center Claim อธิบาย W305 เรื่องการปิดสิทธิ/การอนุมัติ
และเส้นทาง OSR สำหรับรายการ DENY รวมถึงการขอแก้ไขส่งใหม่ D011
รายการ REP ที่ผ่านแล้วอาจยังแก้ไขโดยตรงไม่ได้ ต้องดำเนินการในระบบต้นทางก่อน
[เอกสารชี้แจง Provider Center Claim 30 ต.ค. 2568 (สำเนาเผยแพร่)](https://fliphtml5.com/cxuqh/kzfq/9_Provider_Center_Claim_30_ตค_68/)

แหล่งเหล่านี้เป็นเอกสารชี้แจงที่เผยแพร่ผ่านเว็บไซต์อื่น ไม่ใช่การยืนยันประกาศ
รอบปัจจุบันทุกกองทุน โปรแกรมจึงไม่กำหนดเส้นตายทักท้วงหรืออนุญาตส่งใหม่
ตามรหัสโดยอัตโนมัติ ให้ตรวจประกาศและสถานะล่าสุดในระบบกองทุนก่อนดำเนินการ

| กลุ่มคำแนะนำ | การตรวจต่อ |
| --- | --- |
| W305 / D305 | ตรวจปิดสิทธิและสถานะอนุมัติ SMCS |
| D001 / D010 / D012 / D013 | ตรวจการทักท้วง/ผลพิจารณาใน OSR |
| D011 | ตรวจว่าระบบเปิดแก้ไขแล้วและมีสิทธิส่งใหม่ |
| HERB_GB | ตรวจรอบประมวลผลและประกาศกองทุน |
| อื่น ๆ / ไม่ทราบเหตุผล | อ่านเหตุผลต้นฉบับ ตรวจหลักฐานและยืนยันช่องทางเอง |
| พบยอดจ่ายใน Visit/TRAN_ID เดียวกัน | ตรวจระดับรายการก่อน ไม่เลือกส่งซ้ำทั้ง Visit |

## ขอบเขตข้อมูลและข้อจำกัด

- ใช้ `repstm_statement_data` ของ STM ที่ `paid_amount = 0` หรือยังไม่ระบุ
  และลองอ่านยอดจ่ายที่ระบุชัดจากแถวต้นฉบับโดยไม่เขียนแก้ไขฐาน
  พร้อมแถว `repstm_import_row` ในชีตชื่อ Sheet 0 / Data sheet 0 / 0
  ที่ยังไม่ได้แปลงเป็น statement ใน batch เดียวกัน ชีตชื่ออื่นต้องตรวจการนำเข้า
  และการจัดประเภทก่อน รายการยังไม่นำเข้าจะไม่ปรากฏ
- เก็บ provenance: ID แถว, Batch, ไฟล์, ชีต, แถวข้อมูลนำเข้าเมื่อมี, TRAN_ID,
  แถวต้นฉบับ JSON; เลขแถวข้อมูลนำเข้าไม่รับรองว่าเป็นเลขแถว Excel จริง
- ยอดว่าง/อ่านไม่ได้แยกจากยอด 0 ไม่เลือกส่งใหม่ได้
  Visit ที่มีแถวอื่นไม่ทราบยอดจ่ายก็ยังเลือกส่งใหม่ไม่ได้
  การจับคู่ใช้ VN/AN + HN หรือ TRAN_ID + HN ที่ได้ Visit เดียวใน REP
  แล้วตรวจ VN/AN + HN กับ HIS อีกครั้ง ไม่เลือก Visit แรกจากหลายผลลัพธ์
- รายการ 0 ระดับ item อาจอยู่ใน Visit ที่มีเงินแล้ว จึงตรวจจ่ายจากทุก batch
  ที่ยังใช้งานและปิดการเลือกทั้ง Visit เมื่อพบยอดจ่ายบวก เป็นแนวทางระวังส่งซ้ำ
  ไม่ใช่ข้อสรุปว่า item นั้นไม่มีสิทธิทักท้วง
- ตัด batch ที่มี batch อื่นทดแทน ไม่ลบประวัติต้นฉบับ
- สรุป STM0 นับแถว ไม่ใช่ผู้ป่วย/Visit ไม่บวกรวมยอดเป็นเงินที่เรียกคืนได้
  และไม่บวก STM กับ INV เป็นรายรับ เนื่องจากอาจเป็นการอ้างเงินเดียวกัน
- ชุด audit เกิน 20,000 แถวจะให้ลดช่วงวันที่ ไม่รายงานยอดรวมจากข้อมูลตัดทอน
  ฐาน HIS/STM อ่านไม่ได้แสดงข้อผิดพลาด ไม่อ้างผลสำเร็จจากข้อมูลไม่ครบ
- รายการที่เลือก/บันทึกตรวจสอบอยู่ในหน้าปัจจุบันและไฟล์ที่ดาวน์โหลด
  โหลดใหม่/เปลี่ยนหน้าล้างการเลือก ยังไม่มีทะเบียนติดตามผู้รับผิดชอบถาวรหรือ
  ระบบแจ้งเตือนอัตโนมัติ งานปิดรายการต้องอาศัยการนำเข้าผลรอบใหม่มาตรวจ
- หน้าตรวจสอบใช้สิทธิเมนู `stmZeroAudit` หรือสิทธิกระทบยอด `reconciliation` เดิม
  ผู้ดูแลกำหนดสิทธิเมนูใหม่ได้ในสมาชิกและสิทธิ์เมนู โดยไม่ได้เปิดสิทธิให้ผู้ใช้ทุกคน
  การส่งออกต้องมีสิทธิ OPD/IPD
  เดิมด้วย ไม่ขยายสิทธิส่งข้อมูลหรือเปลี่ยนฐานโรงพยาบาล

## การตรวจสอบก่อนใช้งานจริง

เลข `TRAN_ID` เป็นเลขธุรกรรม ไม่ใช่ AN หรือ VN ตัวอ่านคอลัมน์รหัสใช้ชื่อ
คอลัมน์ตรงกันหลังปรับช่องว่างและเครื่องหมาย จึงไม่อ่าน `AN` จาก `TRAN_ID`
หน้าตรวจ STM 0 แสดงเลขธุรกรรมแยกจากเลข Visit ที่ยืนยันกับ HIS แล้ว
ข้อมูลเก่าที่เคยอ่าน TRAN_ID เป็น AN จะตรวจใหม่ขณะอ่าน โดยไม่แก้ฐานข้อมูล
ต้นฉบับและไม่จำเป็นต้องลบไฟล์นำเข้า ไฟล์ OP/OPUCS ใช้ประเภทผู้ป่วยนอก
จับคู่ HN และวันรับบริการกับ HIS หากต้นฉบับระบุเวลา ใช้ช่วงนาทีนั้นรองรับ
ไฟล์ที่ไม่เก็บวินาที ต้องพบเพียง Visit เดียวจึงจับคู่ได้ หากหลาย Visit หรือ
ไม่พบ จะแสดงรอจับคู่และไม่อนุญาตเลือกเตรียมส่งใหม่

ทดสอบกับสำเนาไฟล์ที่ตัดข้อมูลส่วนบุคคล: ศูนย์จริง, ยอดว่าง, รายการไม่พบ HIS,
TRAN_ID จับคู่หลาย Visit, Visit ที่มีทั้งแถวศูนย์และมีเงิน, ไฟล์ที่ถูกนำเข้าทดแทน
และกรณีมีผลจ่ายใหม่ระหว่างเลือกกับเปิดส่งออก ตรวจจำนวนแถวกับไฟล์ต้นฉบับ
ก่อนนำรายงานเสนอผู้บริหาร โดยเฉพาะรูปแบบ Sheet0 ของแต่ละกองทุน
